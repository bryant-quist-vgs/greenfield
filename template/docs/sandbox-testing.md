# Sandbox testing

How an agent verifies @@PROJECT_NAME@@ from end to end inside its
[sandbox](glossary.md#sandbox), without the help of the
[operator](glossary.md#operator). This is the home of the end-to-end test plan;
[design.md](design.md) links here. Terms are defined in the
[glossary](glossary.md#definitions). Sections marked with a
[stub marker](glossary.md#stub-marker) are not yet written; backlog B004 writes them,
before the components are designed: a design that cannot be tested end to end in the
sandbox is changed until it can be.

## 2. The sandbox

> **GREENFIELD-STUB** State what an agent session in this project can and cannot do, as
> observed and not as assumed: which directories it may write; whether it has network
> access and to where; whether it may listen on a port; whether it may start long-running
> processes, containers, or virtual machines; which credentials it lacks. Each "cannot"
> that a scenario needs becomes a row in §3.
